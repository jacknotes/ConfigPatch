# 参数配置支持正则匹配（方案 B 完整版）设计

日期：2026-08-25
状态：已批准（方案 B：单个总开关，覆盖配置文件名称 + 原字符串，新字符串支持捕获组引用）

## 目标

为参数配置增加一个「启用正则匹配」开关。默认不勾选 = 精确匹配（现状完全不变）；勾选后：
- **配置文件名称**：逗号分隔的多个正则，对**整个文件名**做完整匹配（自动加 `^...$` 锚定），保持不区分大小写（Windows 文件系统本身不区分大小写）。
- **原字符串**：RE2 正则，默认**区分大小写**（需 `(?i)` 前缀声明不区分），用于扫描命中与执行时复检。
- **新字符串**：支持 Go 替换语法捕获组引用（`$1`~`$9`、`${name}`、`$name`），`$$` 表示字面 `$`；未勾选时 `$` 原样输出（现状不变）。

## 交互与 UI

参数配置区新增复选框 **「启用正则匹配」**，放在「允许仅大小写变更」旁边，默认不勾选。勾选后：

1. 「允许仅大小写变更」复选框**自动禁用**——正则下该开关无意义（正则默认区分大小写，用 `(?i)` 控制）。
2. 参数配置区的说明文字切换为语义提示：正则默认区分大小写、`(?i)` 前缀不区分、新字符串 `$1` 是捕获组引用、`$$` 是字面 `$`、RE2 引擎不支持 lookaround 与模式内反向引用 `\1`。
3. 三个输入框（配置文件名称 / 原字符串 / 新字符串）的悬停提示在勾选时切换为正则版文案：
   - 名称：`多个正则用逗号分隔，须匹配整个文件名（自动 ^...$），不区分大小写`
   - 原字符串：`RE2 正则，默认区分大小写；(?i) 前缀表示不区分大小写`
   - 新字符串：`支持 $1/${name} 捕获组引用；$$ 表示字面 $`
4. 开关状态随配置方案自动保存 / 加载 / 回滚（见持久化节）。

## 核心逻辑（core）

### 数据模型

`core.Config` 增加 `RegexEnable bool`。在 `Validate` 之后增加一次编译步骤（扫描/执行开始时各编译一次并复用）：
- 文件名正则：每个逗号分隔项编译为 `(?i)^(?:<pattern>)$`（自动加不区分大小写 + 完整匹配锚定）。
- 原字符串正则：编译 `oldValue` 为 `*regexp.Regexp`。

编译失败在扫描/执行前拦截，弹框指出「配置文件名称第 N 项」或「原字符串」正则非法，并附 `regexp.Compile` 的错误信息。

### 匹配

- 文件名：`re.MatchString(fileName)`（fileName 为 `d.Name()`，不含目录）。
- 原字符串（正则模式）：`oldRe.MatchString(text)` 判断命中；扫描（`Scan`）与执行时复检（`ExecOne`）都使用它。

### 替换

`regexp.ReplaceAllString(text, newValue)`，天然支持捕获组引用。替换计数 `ReplacedCount` 用正则匹配次数（`FindAllStringIndex` 的长度，或对 `ReplaceAllString` 前后命中计数）。

### 校验（修订）

覆盖后重新读取文件、按原编码解码，与本次生成的新文本 `newText` 做**整文件文本比对**：
- `verifyText == newText` 即通过；
- 不一致则走现有自动回滚（`overwriteFile(h.Path, backupPath)`）。

精确 / 正则两种模式**统一使用这一套校验**，不再检查「是否包含新字符串字面量」或「正则是否已无命中」。理由：
- 校验的真实目的是确认覆盖写入生效（防 IIS 锁定、半写、编码损坏），而非验证正则语义；
- 新字符串本身是否命中原正则（如 `version="\d+"` 替换为 `version="2026"`）、`$1` 展开成什么，都不影响校验，避免误判回滚。

### 拦截逻辑

正则开启时跳过「新值=原值 / 仅大小写」检查（正则无法与字面量比较），该复选框同时被禁用。精确模式下维持现状逻辑。

## 持久化与兼容性

`configstore.Profile` 增加 `RegexEnable bool \`json:"regexEnable,omitempty"\``；以下同步接入：

- `Profile.Equal`（历史去重 / 回滚比较）
- `main.collectProfile` / `main.applyProfile`（界面采集与回填）
- `main.buildConfig`（组装 `core.Config`）
- `main.go` 中 `CaseOnlyAllow` 复选框的联动禁用逻辑

旧 config.json 无 `regexEnable` 字段 → 解析为 `false` = 精确匹配，**完全向后兼容，无需迁移**。`CaseOnlyAllow` 已存在字段不变。

## 错误处理与边界

- **非法正则**：扫描/执行前 `Validate` 后编译拦截，弹框指明具体是哪一项（配置文件名称第 N 项 / 原字符串）及其语法错误。
- **RE2 限制**：模式内不支持 lookaround（`(?=...)`、`(?<=...)`）与模式内反向引用（`\1`）；替换侧支持 `$1`。帮助文本中写明。
- **替换结果仍命中原正则**：如 `version="\d+"` → `version="2026"`，替换后正则依然有命中——校验采用整文件文本比对，不受影响，正常通过。
- **执行时复检**：命中文件在执行时已不再命中原字符串（正则）→ 跳过，不备份，与精确模式一致。
- **备份范围**：只有「文件名命中 + 执行时内容仍命中」的文件才会被备份；文件名命中但内容不含原字符串的文件不进命中列表、完全不会触碰。

## 影响文件

- `core/core.go`：`Config` 加字段、编译步骤、匹配 / 替换 / 校验改造、`Scan` / `ExecOne` 分支。
- `core/core_test.go`：新增/调整测试（正则扫描、正则替换+捕获组、整文本校验、非法正则、文件名完整匹配、`(?i)`）。
- `main.go`：UI 复选框、联动禁用、ToolTip 切换、`collectProfile` / `applyProfile` / `buildConfig` 接入、说明文字。
- `configstore/store.go`：`Profile` 加字段、`Equal` 接入。
- `README.md`：功能特性、使用说明、RE2 限制说明。

## 验证标准

- 精确模式（默认）行为与现状完全一致（回归测试全绿）。
- 正则模式：文件名 `^web-.*\.config$` 只命中完整文件名；原字符串 `(?i)` 大小写可控；新字符串 `$1` 捕获组正确展开；`$$` 输出字面 `$`。
- 替换后校验采用整文件文本比对；`version="\d+"` → `version="2026"` 正常通过、不回滚。
- 非法正则被拦截并提示具体项；旧 config.json 无 `regexEnable` 时按精确模式加载。
